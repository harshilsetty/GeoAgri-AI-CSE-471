## 1. Executive Summary

A programmatic, evidence-based quality audit of the local image dataset associated with `archaeological-site-segmentation (seg-v1)` was conducted. Every image and annotation file across all splits was decoded, inspected, and cross-referenced.

### Key Audit Findings

1. **Physical Dataset Verified:**
   - The local dataset exists at `..\Archaeological-Site-Mapping-AI-V2\Archaeological-Site-Mapping-AI-V2\dataset`.
   - Exactly **740 images** and **740 annotation files** exist across three splits: **648 Train**, **61 Validation**, and **31 Test** images (matching the reported Roboflow counts).
   - All 740 images are valid 640 $\times$ 640 JPEGs. Zero files are corrupted or blank.
2. **Critical Flaw 1 — Severe Cross-Split Scene Leakage (P0 Blocker):**
   - The 740 images are **not** 740 distinct real-world scenes. They represent heavy online augmentations of only **128 unique source photographs** (e.g., `hampi_01` to `hampi_70`, `khajuraho_01` to `khajuraho_10`).
   - **70.6% of Validation scenes (36 of 51)** also appear in the Training split!
   - **77.8% of Test scenes (21 of 27)** also appear in the Training split!
   - **5 physical scenes appear simultaneously in all three splits (Train, Valid, and Test)!**
   - *Impact:* The test and validation sets do not measure out-of-sample generalization. Any reported validation mAP is severely inflated by memorization of identical scenes under rotation/shear.
3. **Critical Flaw 2 — Pseudo-Segmentation / Oriented Bounding Boxes (P0 Blocker for Segmentation):**
   - Every single one of the **18,458 labeled instances** has **exactly 4 points (8 normalized coordinates)**.
   - There are zero arbitrary polygon masks. The annotations are **Oriented Bounding Boxes (OBB) / rotated rectangles**, exported as 4-vertex quadrilaterals.
   - *Impact:* This dataset is an Oriented Bounding Box (OBB) dataset, **not** a true instance segmentation dataset. Training a YOLO Instance Segmentation model (`yolo-seg`) on 4-point rectangles forces the model to predict rotated bounding boxes rather than morphological terrain/canopy contours.
4. **Critical Flaw 3 — Extreme Class Imbalance:**
   - 10,620 vegetation instances (present in 100% of images) vs. only 230 structure instances.
   - The class ratio between `vegetation` and `structures` is **46.2 to 1**.
5. **Annotation Quality Issues:**
   - **198 instances** contain normalized coordinates outside $[0.0, 1.0]$ (e.g., $-0.072$ or $1.068$) generated by unclipped Roboflow rotational augmentations.

## 6. Dataset Split Integrity & Data Leakage Audit

A deterministic source-scene decomposition was performed by parsing the Roboflow image naming pattern (`<source_id>_jpg.rf.<hash>.jpg`):

```
Reported Total Images: 740
Actual Unique Real-World Source Photographs: 128
Mean Augmentation Factor: 5.78 augmented crops per source image
```

### Cross-Split Overlap Matrix

```
                      Train (108 scenes)    Valid (51 scenes)    Test (27 scenes)
Train (108 scenes)          108                    36 (70.6%)           21 (77.8%)
Valid (51 scenes)            36                     51                   8 (29.6%)
Test (27 scenes)             21                      8                  27
```

### Critical Findings on Leakage
1. **77.8% Test Contamination:** 21 of the 27 unique scenes in the test set are already present in the training set under different rotations, crops, or color balances.
2. **70.6% Validation Contamination:** 36 of the 51 unique scenes in the validation set are present in the training set.
3. **Scenes in All Three Splits:** The following physical sites appear in Train, Valid, AND Test simultaneously:
   - `hampi_34`
   - `hampi_41`
   - `khajuraho_07`
   - `khajuraho_09`
   - `patadakal_06`
4. **Consequence:** The validation and test sets evaluate **memorization of familiar landmarks**, not true out-of-distribution visual generalization. Evaluating a model on this test set will yield misleadingly high performance metrics.

## 10. Remediation Plan

### **P0: Blocking Trustworthy Evaluation (Must Resolve First)**
1. **Site-Aware Group Splitting:** Re-split the 128 unique base scenes so that **no base scene appears in more than one split** (e.g., 90 scenes for Train, 20 for Valid, 18 for Test).
2. **Format Realignment:** Either:
   - Train as a **YOLO Oriented Bounding Box (OBB)** model (`yolo-obb`), which matches the 4-point quadrilateral annotations natively, OR
   - Re-annotate with true polygon masks in Roboflow if genuine instance segmentation is strictly required.

### **P1: Material Quality Improvements**
3. **Clamp Out-of-Bounds Vertices:** Clip all normalized coordinates to $[0.0, 1.0]$ to eliminate the 198 out-of-bounds coordinate warnings.
4. **Augment Minority Classes:** Collect and annotate at least 300 additional `structures` instances to balance against the 10,620 vegetation instances.
5. **De-duplicate Train Partition:** Remove the duplicate pair (`hampi_31`).

### **P2: Future Architectural Extensions**
6. **Add Agricultural / Soil Classes:** Introduce `bare_ground` and `agricultural_field` classes if direct visual erosion modeling is required.

---

## 11. Final Recommendation

* **Is the dataset ready for YOLO26 Instance Segmentation?**  
  **NO.** The annotations are Oriented Bounding Boxes (4 vertices), not segmentation polygons, and the 77.8% cross-split leakage prevents trustworthy evaluation.
* **Is the dataset ready for YOLO Oriented Bounding Box (OBB) Detection?**  
  **YES, SUBJECT TO RE-SPLITTING.** The annotations are natively structured for OBB detection once the cross-split scene leakage is rectified.
